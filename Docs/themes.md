# Themes And Routes

The default portfolio remains at `/` (Chinese) and `/en/` (English). It uses the shared `BaseLayout`, global token system, and section-based navigation. Desktop uses native vertical scroll snap. Mobile uses threshold-based section navigation for viewport-sized sections and natural scrolling for sections whose content is taller than the viewport.

The default Works section has three distinct navigation levels. `SlidePager.astro` owns the fixed right-side section pager; the Lock Knock screenshot carousel owns its local three-dot pagination; and `Works.astro` owns the bottom-centered `PREV / current / total / NEXT` project navigation. Project changes are manual (buttons, left/right keys, or horizontal swipe) and loop at either end; they do not autoplay or expose screenshot-style dots/progress bars.

On mobile, each Works project targets one dynamic viewport. Project copy and media use viewport-relative positioning, while the project navigation stays above the bottom safe area. Viewports shorter than 700 pixels use a 700-pixel section that can be naturally scrolled, preventing copy and media from being clipped. The Lock Knock poster covers the complete panel and the screenshot carousel retains partially visible, edge-faded neighboring frames without per-slide opacity or scale transitions.

Mobile vertical gestures use a distance threshold of 12% of the viewport, clamped between 72 and 120 pixels. A qualifying gesture moves at most one section. A shorter gesture on a viewport-sized section returns to that section; a taller section continues normal document scrolling and only moves to an adjacent section when swiped beyond its top or bottom boundary. Horizontal gestures must be clearly dominant before Anime or Works consumes them, and the Works screenshot carousel takes priority over the outer project carousel.

`BaseLayout.astro` is the single owner of active-section state, hash navigation, browser history restoration, and mobile vertical gestures. Navigation links and the desktop pager use the same hash-link interception path. Section content remains visible by default and animation hiding is enabled only after the client controller initializes, so a script or observer failure cannot leave the welcome screen blank. Opening the mobile menu applies the shared navigation lock, and reduced-motion users receive immediate section navigation without entrance hiding.

`/battlefield/` (Chinese) and `/en/battlefield/` (English) are self-contained alternate portfolio presentations. They deliberately do not import `BaseLayout` or `global.css`, so their dark tactical palette, condensed typography, and full-screen image showcase cannot alter the default editorial theme. The default navigation exposes the locale-matched route as the Tactical Theme entry.

## Battlefield Theme

- The hero atmosphere is CSS-only: gradients, fixed grid lines, blurred smoke layers, and light beams. No third-party game imagery or branding is used.
- `src/components/battlefield/BattlefieldPage.astro` owns localized copy, showcase data, responsive styling, and the small keyboard/button carousel behavior. The thin route files at `src/pages/battlefield.astro` and `src/pages/en/battlefield.astro` supply the locale. This avoids duplicated page markup.
- The theme covers a mission brief, operator profile, current operations, full-screen project showcase, and contact section. The header language link switches directly between the two static routes.
- On screens wider than 720px, these five content sections use native CSS Scroll Snap with `proximity`, so section boundaries feel guided rather than forcibly snapped. Scrollbars are visually hidden while scrolling, keyboard navigation, touch scrolling, and anchor links remain available. Mobile uses normal continuous scrolling to prevent content clipping.
- `BattlefieldPage.astro` uses one `IntersectionObserver` to mark the viewport-centered section as active. Active scenes reveal titles through a clipping mask, stagger supporting panels, animate the Hero grid and light beam, and scan current-operation status lines. The effect uses CSS transforms and opacity only; `prefers-reduced-motion` disables both section animation and snap behavior.
- A fixed, CSS-only combat-effects layer sits above scene backdrops but below interactive content: five intermittent bullet trails, nine long-cycle smoke plumes, and a low fire field with sixteen rising embers. The layer is pointer-inert, has no third-party assets or canvas loop, and is hidden for `prefers-reduced-motion` users.
- On fine-pointer devices, the fixed tactical crosshair follows pointer coordinates with a requestAnimationFrame interpolation loop. Its horizontal and vertical guides have a center gap around a glowing orange point, matching a modern game HUD. It stays above scene backdrops and effects but below page content, while the Hero's former center cross is now a subtle repeating grid. The crosshair is omitted on touch devices and for `prefers-reduced-motion` users.
- Existing project screenshots are imported through Astro's asset pipeline and rendered in the large-screen showcase. Each slide has its own type, description, image position, and optional external project URL.
- The showcase supports previous/next buttons and left/right keyboard navigation. Reduced-motion users receive non-animated transitions.

When adding a showcase project, append an item to the `works` array in `src/components/battlefield/BattlefieldPage.astro`, supply an imported local image, and add matching Chinese and English metadata. Run `npm run check` and `npm run build` after changes.
